redis存储记忆
初始化：
输入 - > 旅行和旅行成员信息 + 系统提示词
输出 - > 行程和行程明细
记忆：不需要
更新：
输入 - > 旅行和旅行成员信息 + 代应用ai的一问一答 + 原本的行程和行程明细 + 系统提示词
输出 - > 新的行程和行程明细
记忆：大模型的记忆
ai回复
输入 - > 旅行和旅行成员信息 + 行程和行程明细 + 用户问题 + 系统提示词
输出 - > ai回复（普通回复 + 建议回复）
记忆：大模型的记忆

问题：由于使用redis自动存储大模型的记忆，会出现行程信息累加的问题，
比如：
第一次：
    输入：行程A
    输出：行程B
第二次：
    输入：行程B + 行程A + 行程B（记忆包括了第一次的输入和输出）
    输出：行程C

解决办法：
    1、不使用redis自动存储大模型记忆，大模型只一问一答，不实现记忆功能
    2、redis只存储最近 10 轮与ai纯问答

初始化：
    输入 - > 旅行和旅行成员信息 + 系统提示词
    输出 - > 行程和行程明细
    记忆：无
    存储：生成的行程和明细保存到数据库
更新：
    输入 - > 旅行和旅行成员信息 + 代应用ai的一问一答 + 原本的行程和行程明细 + 系统提示词
    输出 - > 新的行程和行程明细
    记忆：无聊天历史记忆，只使用本次选中的建议问答和最新业务数据
    存储：生成的行程和明细保存到数据库
ai回复
    输入 - > 旅行和旅行成员信息 + 行程和行程明细 + 用户问题 + 系统提示词 + 最近 10 轮与ai纯问答（从redis缓存读取）
    输出 - > ai回复（普通回复 + 建议回复）
    记忆：不使用框架自动持久记忆，历史由业务主动传入
    存储：redis仅追加“用户身份、原始问题、AI 回复”，生成的ai回复保存到数据库
