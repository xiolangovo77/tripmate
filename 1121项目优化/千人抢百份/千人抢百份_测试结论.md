# 会员额度秒杀 · 1,000 名会员抢 100 份实测

2026-11-22 在单个 Spring Boot 测试实例上，1,000 名不同的有效会员各领取一次，活动库存为 100 份，每份含 5 次 AI 使用额度。100 名会员各到账 1 份，900 名收到售罄，剩余库存 0 份，超发 0 份。

| 核对位置 | 实测结果 |
| --- | --- |
| HTTP 请求 | 1,000 个独立测试账户通过真实 HTTP 登录，获得 1,000 个不同的会话。1,000 个客户端虚拟线程就绪后同时放行。100 个请求返回不同的领取单号及 `PROCESSING`，900 个返回“活动已售罄”，其他错误 0 个。 |
| Redis 预扣 | 剩余库存 0 份，100 条用户领取标记逐笔匹配成功请求的用户和单号。开始投递前，Stream 中有 100 条待办。 |
| 投递与入账 | 投递器只读取本次活动的 Stream，由生产消费者处理独立 RabbitMQ 队列。投递后 Stream 清空，待投递索引只剩总份数标记，死信队列为空。 |
| MySQL 对账 | 共 100 张已到账领取单、100 条发放流水。按成功请求的用户和单号逐笔核对，每条流水为 5 次，对应会员余额为 5 次。全部测试账户余额合计增加 500 次，漏发、超发和重复入账均为 0 份。 |

本轮从并发放行到收到全部 HTTP 响应为 1,176 ms。为能核对投递前的 100 条 Stream 记录，测试在收齐领取响应后才启动本活动的投递，因此该时间仅覆盖领取请求。测试使用本机 HTTP 直连以及开发环境的真实 MySQL、Redis、RabbitMQ。登录提前完成，测试上下文未加载登录限流切面。

在 `tripmate` 模块目录复验：

```powershell
mvn "-Dtest=QuotaFlashSaleIT" "-Dquota.dev.it=true" test
```

本轮输出：

```text
FLASH_VERIFIED activity=14 members=1000 accepted=100 soldOut=900 stock=0 granted=100 flows=100 balance=500 oversold=0 elapsedHttpMs=1176
```

用例结束后清理临时活动、用户、领取单、余额、流水、Redis key 和专用队列。同一用户重试 100 次的独立验收记录见[第二步测试结论](第二步_Lua预扣与可靠投递_测试结论.md)。
