# 行程自动同步

AI 行程页与成员列表共用一条 `GET /api/trip/{tripId}/events` SSE 连接，携带 Session Cookie。收到 `trip.itinerary.changed` 后，按旅行 ID 查询 `GET /api/itinerary/getByTripId?tripId=...`，同步标题、概述、费用、明细和草案/确认状态。生成、采纳建议替换行程、确认行程均会触发后端提交后的事件。

## 前端职责

- `useTripEvents`：管理连接、权限失效、重连、页面可见性、网络状态及每 30 秒的前台兜底查询。不同业务注册各自的事件处理函数；未监听的事件被忽略，不影响连接。
- `useTripSnapshot`：各业务独立管理查询、取消请求、错误和待刷新标记。同一业务查询期间收到新事件，会在查询结束后补查；过期响应不能覆盖当前数据。
- `useTripMembers`：更新成员信息。
- `useTripItinerary`：读取当前行程快照，更新当前行程 ID，并在所选天数仍存在时保留选择。

自动查询成功后替换行程数据，不重新挂载整个页面，保留聊天输入及建议选择。首次加载失败显示重试入口；后续同步失败保留上一次内容并提示错误。新接口返回 null 时展示尚未生成行程。

本页面生成、修改或确认期间暂停后台行程查询并记下变更，避免操作前的查询结果覆盖新行程。写操作完成后主动查询当前快照；操作结束时如仍有待处理事件则继续同步。写请求超时后只补查，不自动重发写请求。确认弹窗打开期间若行程 ID 已变化，停止提交并提示重新查看。

SSE 不提供历史事件重放，连接打开、恢复联网、页面重新可见时均补查。页面隐藏、断网、切换旅行或卸载时取消查询并关闭连接。没有增加发送节流；查询过程只合并待刷新标记。

## 部署与范围

需要先更新并重启后端，提供新的行程快照接口与事件；前端不回退到两次读取旧行程 ID 和明细的方式。代理配置及单实例广播限制沿用 [成员同步说明](MEMBER_REALTIME.md)。
