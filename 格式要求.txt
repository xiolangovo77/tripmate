代码格式
1、使用普通 Java 类定义模型，不使用 record。模型放在所属业务模块的 model 包下，一个类一个 .java 文件。每个字段使用中文 /** ... */ 注释说明含义，涉及数量、金额或时间时注明单位或取值范围。

2、业务方法使用 //1、、`//2、`、`//3、` 标注主要处理步骤，每个方法从 //1、 开始编号。注释说明这一步的业务目的。

3、注入的依赖字段使用类型名首字母小写的驼峰命名，例如 UserService userService、`OrderMapper orderMapper`。每个注入字段使用中文 /** ... */ 注释说明它在当前类中的用途。新增或修改相关类时统一遵循此规则。

4、Mapper 接口与 SQL 分开维护。`XxxMapper.java` 声明数据访问方法，`XxxMapper.xml` 编写 SQL 和结果映射。每个自行声明的 Mapper 方法都要在上方写中文 /** ... */ 注释，说明业务用途，用 @param 说明参数含义，有返回值时用 @return 说明结果含义。涉及空结果、影响行数、行锁、唯一键冲突或状态变更时，写明调用方需要了解的行为。

5、每个自行声明的字段都须在字段上方单独写中文 /** ... */ 注释，说明含义和用途。该规则适用于普通成员字段、注入依赖、静态字段和常量。数量和时长注明单位，脚本字段说明执行时机及主要操作。

6、Redis Lua 脚本统一放在 src/main/resources/lua/ 下，每个脚本一个 .lua 文件，Java 通过类路径加载。文件第一行使用 -- KEYS: 按传入顺序列出键，第二行使用 -- ARGV: 按传入顺序列出参数。涉及多键同槽、时间或数量时注明约束和单位，没有键或参数时在对应行写“无”。

Git 提交说明格式
标题使用“主题 - 核心改动”。标题与正文之间空一行，正文使用 1、、`2、`、`3、` 分条说明。每条写清“改了什么 - 起什么作用”，按需点明类名、方法名或文件名。
主题 - 一句话概括本次核心改动

1、新增 Xxx 类 - 说明它负责的功能。
2、调整 Xxx 方法 - 说明改动解决的问题。
3、补充 Xxx 测试 - 说明验证的场景或结果。
